# Curation and verification policy

AmeenLibrary follows a **hybrid curation model**: the maintainer's personally tested resources are the foundation, and community contributions are welcome.

## Verification labels

- **Personally Verified:** The maintainer has used and evaluated the resource firsthand.
- **Community Verified:** A contributor has tested the resource and supplied enough reproducible detail for maintainers to assess the claim.
- **Not Yet Verified:** A candidate awaiting sufficient evidence or review. This is a submission state, not a published endorsement; keep it in a pull request or a clearly separated candidate area.

Verification means the stated usage was checked; it is **not** a security audit, endorsement, or guarantee of continued compatibility.

## Agent support

Prioritize accurate, practical installation and usage guidance for **Codex** and **Claude Code** first. Other agents are welcome, but compatibility must be documented as tested, reported, or not evaluated—never assumed.

## Publishing rules

1. Link to the canonical source and credit the original maintainer.
2. State the license if known; otherwise mark it unconfirmed and link rather than copy third-party material.
3. Provide prerequisites, setup steps, a practical example, limitations, and verification evidence.
4. Explain required authentication and permissions without including tokens, passwords, or credential values.
5. Avoid publishing private configurations, personal data, or internal project details.
6. Review contributions through pull requests; do not mark a resource personally verified based solely on someone else's claim.
7. Update verification dates only after rechecking the resource.

Use [the resource entry template](resource-template.md) for new submissions.
